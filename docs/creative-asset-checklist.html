B · Machine & Game Surfaces (we believe these are always required)

The core branded surfaces on the machine and in the game. Confirm each spec is right.

B1 Payment Terminal Screen

What it is: the static image shown on the card-payment screen on the machine. Our current spec: PNG or JPG · 1080 × 1920 px (portrait) · under 150 kb. We tell customers to place their logo here because the screen stays lit even when idle. Is this correct?

B2 Product Packshot

A clean cut-out image of the product. Spec: PNG · 428 × 600 px · under 150 kb, with ~30 px right padding on wide items. Customers may optionally also send a decorative “hero” version, but a plain standard packshot is always required because the game uses it. Is this correct?

B2b Must packshots have a transparent background?

Does the standard packshot have to be supplied on a transparent background (no white box)?

B3 Negative Icons

The “wrong” icons players must avoid tapping (the distractors). Spec: PNG · 300 × 300 px · under 50 kb each, on-brand and themed. Minimum is 6. Is the spec correct, and what is the maximum number we'll accept?

B4 Game Page Banner

The header strip across the top of the gameplay screen. Spec: PNG · 1080 × 216 px · under 150 kb. Correct?

C · Videos

The frames give us dimensions but several videos are missing file type, max size and length — please fill those gaps.

C1 Idle Screen Advert spec

The video that plays on the machine when nobody's using it (the attract loop). Spec: MP4 · 9:16 · 1080 × 1920 px · under 20 mb · 15–30 sec. Is this correct?

C1b Is this the same asset as the in-game “looping video”?

We believe the idle/attract video and the in-game looping video are the same single upload (not two separate files). Is that right?

C2 Game Prompt Video — fill the gaps

Short animated “Play now to win” teaser. The frame gives the size (900 × 1600 px, with an 804 × 682 px safe area) but does not state file type, max file size, or length. Please fill those in.

C3 Game Initial Video

The “how to play” clip (e.g. “tap the can when you see it”). We assume same dimensions as the Prompt Video. Confirm, or give its own spec — and add file type / max size / length.

C4 Showcase Video (the “spinning wheel” of prizes)

Used only when there are multiple prizes and the player picks which one they're playing for. We have no spec recorded — please give file type, dimensions, max size and length.

C4b One showcase video for all prizes?

Confirm there's only ONE showcase video covering all the prizes together — not one per prize.

D · Storefront / Homepage (only if the storefront is used)

D1 Home Banner Ad

The big banner at the top of the storefront homepage. Spec: JPG/PNG · total canvas 2160 × 816 px · safe area 2064 × 600 px (keep all text/logos inside it) · 48 px padding · under 150 kb. Correct?

D1b The optional “View Offer” button

Should we ask the customer, per event, whether they want this button — plus its label text and where it links (a product or a category)?

D2 Category Image

The thumbnail for a product-category tile. Spec: PNG · 800 × 512 px · under 150 kb. Only needed if the customer uses the category view (otherwise it defaults to “All Products”). Correct?

D3 Product Details page media

Each product detail page needs 3 pieces of media: Top slot 16:9 (1920 × 1080 px); Left + Right slots 1:1 (1080 × 1080 px). Any can be image or video (JPG/PNG/MP4/WEBP/WEBM) — images under 150 kb, videos under 10 mb & 30 sec. Is “3 media per product” correct?

F · Game Logic & Prize Delivery (confirm our understanding)

This logic decides which assets a customer is even asked for, so it's important we have it exactly right.

F1 The “key icon” (what players hunt for)

Confirm how the key icon — the thing players try to spot and tap — is chosen:
• 1 product → use the product itself.
• Multiple products, won randomly → use a separate brand icon (not a specific product).
• Multiple products, player picks their prize → the key icon swaps to match their chosen prize.
Is this right?

F2 Prize delivery mode

For multi-prize events, we want to ask the customer up front: should prizes be awarded randomly, or should the player choose which prize they're playing for before the game starts? Does that match how it actually works?

F3 Maximum number of prizes

We're assuming a machine can be set up for up to 6 prizes/products, with more than 6 only by special request. Is 6 the right ceiling?

F4 What scales with more prizes?

Confirm: no matter how many prizes there are, the videos stay one generic set — the only thing that increases per prize is the packshots (plus optionally the one showcase video). Right?
